Emotion Detection Assistant

Python OpenCV AI HCI

The Problem

Most apps treat every user the same way, no matter how they're feeling. I wanted to build something that could actually notice if someone was happy, sad, stressed, or tired — and respond differently based on that, just like a friend would. I was inspired by learning about AI in school and wanting to make it more human.

The Process

1. Emotion Detection: Used Python with OpenCV and the DeepFace library to detect facial expressions through a webcam.
2. Emotion Classification: The system identifies emotions like happy, sad, angry, surprised, neutral.
3. AI Response System: Built an interactive AI that changes its replies/tone based on the detected emotion.
4. Output: The system shows the detected emotion on screen and the AI responds accordingly via a Tkinter interface.

The Challenges

At first, the model kept confusing 'surprised' with 'scared'. I fixed this by adjusting the confidence threshold. Also, the webcam detection was slow on my laptop, so I reduced the frame rate and resized the input image to make it process much faster in real-time. Getting the AI to respond naturally to each emotion took several tries — I had to write different reply sets for each mood.

The Result

The final system can detect emotions in real-time through a webcam and have the AI assistant respond with supportive or matching replies. Detects emotions with about 85% accuracy and responds in under 0.5 seconds.

What I'd improve next

Add voice tone detection along with facial expression (multi-modal emotion detection). Make the AI's replies more personalized over time (remembering mood patterns). Build a simple mobile app version.

Obstacle-Avoiding Robot

Arduino Sensors C++

The Problem

I wanted to build a robot that could navigate a maze without human intervention, ensuring it wouldn't crash into walls.

The Process

I started with a basic chassis and DC motors. Initially, the robot kept crashing because the ultrasonic sensor was checking distances too slowly. The robot would move forward before realizing a wall was already there.

The Solution

I rewrote the Arduino code to use interrupts and non-blocking delays (millis() instead of delay()). This allowed the robot to read sensor data while simultaneously turning the wheels.

The Result

The robot successfully navigated a homemade cardboard maze. Reduced wall collisions by 100% and improved maze completion time by 15 seconds.

What I'd improve next

Add infrared sensors on the sides so it doesn't just look straight ahead, allowing it to hug walls perfectly.

Line-Following Robot

Arduino IR Sensors

The Problem

Factory automation relies heavily on AGVs (Automated Guided Vehicles). I wanted to understand the core logic by building a miniature version that follows a black line.

The Process

I used two IR sensors pointing down. The main bug I faced was "jittering"—the robot would rapidly shake left and right instead of moving smoothly forward.

The Solution

I learned about PWM (Pulse Width Modulation) and adjusted motor speeds dynamically instead of just turning them on/off fully. This created smoother turning arcs.

The Result

A stable robot that follows complex curves. Completed an S-curve track in 12 seconds with zero line departures.

Simple Python Chatbot

Python NLTK

The Problem

I wanted to see how computers process human language (NLP) before tackling larger AI models.

The Process

I started with a massive if/else block, but it became unmanageable quickly. If the user said "hello" instead of "hi", it broke.

The Solution

I integrated basic Natural Language Processing (NLTK) to tokenize words and match intents, rather than looking for exact string matches.

The Result

A CLI-based assistant that can answer questions about my school schedule. Handles 20+ different conversational intents.
